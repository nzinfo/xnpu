## 1. 器件抽象与结构常数

### 1.1 被建模的机器（只列模型用到的结构事实）

- **阵列**：npu2 分区 = 计算核阵列 + shim DMA 行。整器件 8 shim 列 × 4 计算
  行 = 32 tile（P28-5）；我方 quad/pair 夹具所用分区 = 8 核（2 列 × 4 行）
  + 4 shim，"IRON 的 8 columns = 8 核，ctrl 列字段 0-3 = shim"（P27-3b）。
- **SHIM CHANNEL LAW**【实锤，静态推演 P28-6a】：每 shim 2 MM2S + 2 S2MM
  → 整器件上限 **16 入流 + 16 出流**。每 worker 1 A fifo + 1 C fifo ⇒
  **N=16 恰好饱和，N=32 在此协议下放不下**。
- **core↔core ObjectFifo = 共享内存 + 锁，不烧流端口**【实锤 P28-3】：
  npu_insts 零 aie.flow/stream 路由；缓冲+锁 home 于一个端点 tile，对端
  经 NoC 远端 L1 读写（acq 返回缓冲指针的 SPSC 队列）。约束因此是
  **L1 容量 + NoC 带宽**，不是流端口数；不相邻端点的 fifo 会拆成
  mem-DMA 流（每核仅 2 出）——HAM16 全单位步哈密顿环就是为了全部
  降形为零流量共享内存（P28-6d/6e）。
- **tile 资源**：计算核数据内存 64KB（4×16KB bank）、MemTile 256KB
  （docs/08 §4b）；PMEM 16KB/核（P19b：loader 只装 16KB，胶水恒 ~3052B；
  P28-4a 软浮点清剿）；栈窗 0x400（STACK LAW，P16/P17）。
- **上下文**：每 workload context 一个固件 ERT 实例，上限 16（docs/08；
  第 17 个 EINVAL），每 ctx 64MB host 指令缓冲（锁页根源）。

### 1.2 硬约束清单（可行性边界，不是时间成本；违反 = 编译期/挂死，不是慢）

| 律 | 内容 | provenance |
|---|---|---|
| SHIM CHANNEL LAW | ≤16 入 + ≤16 出流；每 worker 1+1 ⇒ N≤16 | P28-6a |
| CORE↔CORE FIFO 律 | 两端单步相邻 ⇒ 共享内存+锁；否则烧 mem-DMA（每核 2 出） | P28-6d（源码实锤） |
| STACK LAW | 栈窗 0x400；帧超限溢出写坏 fifo 流（静默） | P16、P17b |
| PMEM 16KB | CDO loader 只装 16KB；胶水 ~3052B；unroll 是 PMEM 之敌；≤16 trip 全展开 | P19b、P28-4a |
| L1 64KB/tile | OF depth × obj × 端点数 + .bss + 栈 ≤ 64KB | docs/08 §4b、P28-6e（高水位 ≤39.9KB） |
| ELEM%64==0 | load_v<256> 需 64B 自然对齐（depth-2 fifo 双元素缓冲） | P11 |
| AIE 向量对齐律 | 自然对齐外**截断不报错**；紧凑子区域 per-position 步长（48B）会静默越界 | P28-4c（反汇编实锤） |
| BD 维律 | ≤4 维/BD、每维 size ≤1023（10 位）、≤16 BD/通道、BD 槽号每组从 0 重数 | P12、P19b |
| 5-BO 律 | NPU ctrl kernel ≤5 张量 regmap（第 6 个 SEGFAULT） | P19b、P20b |
| 每组 ≤4 fill/shim | 前置 fill >4 即 value/描述符失配挂死（2F+1D 已证形为安全核） | P16、P19 |
| ctx 16 / 64MB | 固件 ERT 实例表；memlock 系统性根源 | docs/08 §1 |
| 标量 FPU 不存在 | 标量 float = 软调用（PMEM/时序双输）；浮点必须上向量 | P28-4a |

这些律是**设计空间的多面体**：模型的时间方程只在可行域内取值。工具层
（§8）把它们做成静态检查器（design-time witness），先于任何时间预测。

## 2. 提交路径与完成语义（host 侧成本核 + 正确性律）

一次"运行"在 host 侧穿过以下成本核（全部可加、各自独立实测）：

1. **submit+syncobj 往返 `t_sub` ≈ 33–55 µs**【实锤 P1/P7/P26b-L3】。分桶
   随设备流量单调涨（1-4MiB 55µs / 4-16MiB 70 / ≥16MiB 82，P6）——大 op
   的 solo 里混入排队效应，不是纯 syscall。
2. **SYNC_BO 成本模型（P21-3 修正版，最终版）**【实锤】：
   `T_sync = t_syscall(1–5µs) + D_dirty × r`，其中脏行回写速率
   `r_kernel ≈ 0.2 ns/B（~5 GB/s）`、用户态 CLFLUSHOPT `≈0.03 ns/B
   （~32 GB/s）`；干净行近乎免费。**ToDevice → 用户态 CLFLUSHOPT**（严格
   等价，148KB 4.6µs）；**FromDevice → 必须保留 ioctl**：内核对 ctx BO 的
   MSG_OP_SYNC_BO fw fence 是正确性必需（syncobj 信号时 S2MM 尾写可能仍在
   NoC 途中，P21-3 决定性反例：差 98 字节全落 C BO 最后 128 行）。
3. **exec 边界 `t_exec` ≈ 30 µs**【实锤 P28-4e/5a】：相邻 exec 间的固件
   收尾/上下文交接。FLM 对照：整 token 1 ioctl、33 op 链在一个
   ERT_CMD_CHAIN 里（P23），边界成本被链结构摊薄到 ~µs 量级/层。
4. **cu_mask 翻转 `t_flip` ≈ 500–650 µs**【实锤 P9/P18/P27-3a/P28-5a】：
   fw PDI 重载。单 CU 全走一个 PDI 即免（P27-3a，−1.8ms/token）；lv2 路径
   唯一残留 = lm_head 在 CU1（每 token 1 次，P28-5a）。
5. **完成语义（正确性律，不是时间项）——signal ≠ 成功**【实锤 6f-7，内核
   源码】：`aie2_sched_notify` 在**所有**响应路径（COMPLETED/ERROR/
   TIMEOUT/ABORT/health）都 `dma_fence_signal`。exec BO header u32 的
   bits[3:0] 是状态字（0 INVALID / 1 NEW / 2 QUEUED / 3 RUNNING / 4
   COMPLETED / 5 ERROR / 6 ABORT / 7 SUBMITTED / 8 TIMEOUT / 9 NORESPONSE）。
   health 路径（fw 无响应）会把 health 数据 **memcpy 进 cmd BO 的 data 区
   （覆盖 regmap！）** 并置 TIMEOUT；一旦 `ctx->health_reported` 置位，后续
   所有 cmd 瞬间 ABORT+signal。⇒ **模型的一切"设备时间"都以状态字==4 且
   输出哨兵改写为前提**（§8 回归用例 b）。
   **全部预测已被仪器兑现**【实锤 6f-8 §2】：n@6404 bug 的病理 exec0 =
   TIMEOUT(8)@60.85s + pkt[1..8]=0xffffffff（health memcpy 覆盖 regmap 的
   指纹）；exec1+ = **ERROR(5)**@118–1297µs（fw 对 jammed 队列快速拒绝——
   修正 6f-7 猜的 ABORT）；C 全零 + hash 恒定 = 从未复算。另有一个未解开
   放问题：run-lv2loop 里 10KB C BO 的 FromDevice 恒 EINVAL（os 22，N=8/16
   都是），已用 clflush_region + 2ms settle 绕过（6f-7 §4）——fw-fence
   正确性风险由 hash 跨 exec 稳定性兜底，留观。

## 3. 分层成本核算框架（设备侧）

### 3.1 一次 exec 的分解树

```
T_exec = t_g' + max_r Σ_o u_r(o)        （五维资源包络，维度与常数见 §4.2）
         r ∈ { 字节(DDR/NoC), 通道字节, 元素节拍, 计算块, 依赖段 }
```

分解树各层（自上而下）：

```
exec ── host: submit(t_sub) → fw dispatch → [task groups] → TCT retire →
              syncobj signal（≠成功，§2-5）→ host 读回 coherency(§2-2)
group ── shim/fw 状态机固定成本 t_g + 组内 fill/compute 重叠 + 组末屏障
fill  ── 字节维 B/55.1 与 通道维 B/(n_chan·6.95) 取包络（P13 重叠律）
发行  ── 元素维 n_shim×t_beat（β 条件化，§4.2；第一版的独立"握手和"项
         已被 v5s 反例并进此维——元素税不是无条件串行项）
```

多组 exec（pair/quad 形态）：`T_exec = Σ_groups T_group`（P27-3b【实锤】：
pair probe 547µs ≈ o(175) + gateup(378) 串行和 −6µs；**组间无重叠也无额外
罚金**——每组各付一次 `t_g`）。

多 exec token（lv2 形态）：

```
T_token = Σ_e [T_exec(e) + t_exec + t_sub]  +  T_lm + T_host_serial + K_flip × t_flip
```

### 3.3 关键结构性结论（模型的地基，全部实证）

1. **task group 是调度成本原子**【实锤 P27-4】：ctrl 级重排（输入侧 hoist /
   输出侧 hoist / 删 TCT）全部 NULL 或挂死 ⇒ 组固定成本**不在指令发行时序
   里**，在 shim/fw 对每组的状态机（drain token 集 + 组末 npu.sync 的完成
   路径）。P28-1 修正表述：我们的组末 8 条 npu.sync 是**对真实 drain 完成
   的长等待**，每条付 poll 量子 ~5-10µs × 8 ≈ 75µs；FLM 的 309 TCT 立即
   retire（等一个已完成 token ≈ 免费）。**组只能靠设计时不产生跨组数据
   依赖来减少**（依赖走内核内 L1/.bss 交接，不走 C→DDR→window 往返）。
2. **填充机器，不是计算**【实锤 P27-3b】：v5.4 双累加器内核计算完全藏于
   fill 之后（probe 去计算，时间不变）。当前所有 GEMV 形态的计算项
   `T_comp` 在 max() 里取 fill 支——模型对 decode 工作负载**默认计算免费**，
   除非引入新内核（届时按 P13 每块节拍重测）。
3. **聚合带宽形态相关（非线性）**【实锤】：单列 ~4–6.4 GB/s（P11 2.9–4.9 /
   P26 4.1 我方、6.4 FLM）；lv2 全系 36.1–37.6 且**对 N/环数/计算量全部
   不变**（6f-8/6f-9）；墙 55.1 只被大线性 BD 的 plain/pair 形态达到
   （P27-3b/P12）。§4.2 的五维包络给出统一解释——两个形态绑定的维度
   不同（字节维 vs 元素维）。
4. **队列深度平坦**【实锤 P7】：深度 8→64 每 op 差 ≤4%；变异在**跑与跑
   之间**（板况漂移，同日 ±40%，P7/P21-5）⇒ 模型常数只在同批背靠背 A/B
   内有效，校准必须声明板窗。

## 4. 组合规则（怎么把成本核拼起来）

### 4.1 三条组合律

- **R1 组内取 max（fill/compute 重叠律，P13）**：稳态节拍 = max(t_fill,
  t_comp)/块。当前内核 t_comp 藏于 fill（P27-3b），退化为纯 fill。
- **R2 组间取和（P27-3b）**：同 exec 内多组 = Σ(每组 t_g + 组内 R1)。
  组间零重叠。跨组数据依赖（C→DDR→window 往返）额外把下游组的 fill 串到
  上游组的 drain 之后——这是 pair 比"流和"慢不出来的原因（547 ≈ 553），
  也是 quad 5 组 5×114 拼合的来源（P27-4）。
- **R3 exec 间取和 + host 串行段加和（P28-5 hostprof 闭合）**：
  `T_token = Σ T_exec + T_lm + T_host`。当前链是**零重叠**结构（wait 段
  25.77ms 独占）；FLM 的 host ~2.5ms 与 wait 重叠（双 runlist ping-pong，
  P5）——重叠是调度属性不是器件属性，模型两边都允许。

### 4.2 五维资源向量与包络（元素发行节拍是第五维；6f-8/6f-9 修正版）

**先否证本笔记的第一版公式**（留痕）：
`BW_stream(L) = L/(L/BW_chan + t_bd)` 把 1.2µs/BD 当作**无条件的每元素
协议税**。该式在两个点上"碰对"（N=8 聚合 36.6 预测 vs 36.1 实测；N=16
加宽无收益 743 vs 754），但被 **v5s 反例**否证【实锤 6f-9 §3】：同样的
18560B 元素、同样的 depth-2 fifo 协议——**均匀 fill 设计（v5s/plain）
打到 55.1 墙（每元素 2.67µs = 纯带宽项），layerv2 K 链只有 36.6 GB/s
（每元素 3.9µs）**。税不是元素的固有属性，是**流结构的条件属性**。判别
链（全部实锤）：ring 无罪（r0 无 gather 与 full 只差 ~20µs，6f-9）、计算
无罪（zeros probe vs 真实权重只差 ~20µs，6f-9）、通道数无罪（N=16 饱和
16A+16C 后聚合 36.6 不动，6f-8 §4）、DDR 墙非绑定（55.1 可达，P12/
P27-3b）⇒ **每 shim 的元素发行/协议节拍是一个独立于字节数的资源维度**。

**统一方程【模型，闭合法见 §6】**——TileSight 包络加第五维：

```
T_exec = t_g' + max_r Σ_o u_r(o) ,  r ∈ { 字节, 通道字节, 元素节拍, 计算块, 依赖段 }
```

| 资源维 r | u_r 公式 | 常数与 provenance | 绑定的设计形态 |
|---|---|---|---|
| DDR/NoC 字节 | `B/55.1` | 55.1 GB/s（P27-3b 四点拟合；P12 55.6） | v5s/plain 全系（lm 2660 = 132 + 2528 ✓） |
| shim 通道字节 | `B/(n_chan·6.95)` | 6.95 GB/s/通道（P12 单流实测） | 单通道窄设计（P28-1：4-6 通道×8KB） |
| **shim 元素节拍** | `n_shim × t_beat`，`t_beat = 2.67 + β·1.2 µs`（18560B 元素） | 2.67 = 18560B@6.95；1.2 = 干净元素握手（P28-6f-6）；3.9 实测拟合（6f-9） | **layerv2 全系（β≈1： 190×3.9 = 741µs）** |
| 计算块 | `blocks × t_comp` | ≈0（P27-3b probe；6f-9 zeros 复证） | 当前未绑定（新内核需按 P13 重测） |
| 依赖段 | `n_seg × t_restart` | **未定**（β 的微观机理候选之一，判别在飞 6f-9 §4） | 候选维度 |

两个极限形态在 max() 里**翻面**：
- **均匀连续 fill（β=0）**：元素发行完全藏于字节传输背后——v5s 的
  132µs + B/55.1 拟合、P12 纯 fill 的 1.39µs/9280B 元素（=1.34µs 带宽项，
  零税）、FLM 的算力列纯权重大流（P23-8：零激活 BD，TCT 串在流内当数据
  依赖）。**v5s 就是"零依赖段"的极限点。**
- **K 链分段 fill（β≈1）**：A 流被 K 窗口元素（X/XN/窗口）与 C drain
  穿插分割成依赖段——窗口 fill ← C drain ← 计算 ← 前序 fill 的 exec 内
  串行链，每元素多付 ~1.2µs 串行（节拍 3.9 vs 2.67）。β 的微观机理未判
  （候选清单 6f-9 §3：K 窗口元素穿插打碎大块流 / C drain S2MM 与 MM2S
  同 shim DPU 竞争 / depth-2 内核 acquire 停顿 / 段边界流水重启）；
  **判别实验**：v5s 式 K 头垃圾探针（内核零行、fifo 全跑）vs 6f-6 哨兵
  时间线量单元素间隔分布——若元素间隔均匀 ~3.9µs 指向发行节拍，若间隔
  分段（大块 2.67 + 段首长泡）指向段重启。

**方程的直接工程推论**：
1. **加宽已死**（6f-8 §5 实证 + 模型解释）：lv2 层几何固定总元素数
   （~1500 元素/exec），8 shims 分摊后 `n_shim` 恒 ~190——N=8→16 只改
   每 shim 通道数（1→2），而节拍在 shim 不在通道 ⇒ 聚合不动（36.1→36.6）、
   E2E 设备时间零收益（25.2→25.1ms，6f-8 §5）。通道翻倍是典型的局部
   优化——它优化的是不绑定的维度。
2. **36.6 钉子的解除方向按元素数削减排序**（6f-9 §4）：(a) 元素做大
   （18560→N×；L1 64KB 是硬约束：depth-2×2×元素+21KB .bss 已满，需
   depth-1 或 .bss 减半）；(b) W 走 core mem-DMA（绕 shim 发行，P28-1
   swiglu_fused 机器已证）；(c) 消 K 链分段（窗口/激活走内核内 .bss 交接
   ——P27-4 教科书结论的深化：依赖必须走片上，不走 fifo 流）。解除后
   `T_exec → max(B/55.1, …) ≈ 501µs + 小项`，字节维立即接棒。
3. **与 FLM 差距的结构本质候选**（【推断】，与 P23 解剖自洽）：FLM 整层
   一个 exec、算力列纯权重流入零激活 BD、TCT 串在流内——**无分段大流
   形态，与 v5s 同侧（β=0）**。我方 K 链是 β≈1。每层差 = 流 555µs 相同
   地板 + (741−501) = 240µs 分段税 × 33 exec ≈ 7.9ms/token——恰是
   30.57 与 FLM 21.44 差距的主体。

### 4.3 量化密度：第一性杠杆（超越一切调度优化）

【实锤 P26b】两边（我方/FLM）都流 ~1GB/token 层+lm_head 权重，都在
~50-55GB/s 墙附近：

```
tok/s ≈ BW_eff / 每 token 权重字节        （P26 教科书要点，P26b 修正版归因）
T_floor = W_bytes(密度) / BW_wall
```

g64 共享 scale（0.5625→0.53 B/param）/ W3（0.41）⇒ 地板 18.9→17.8/13.8ms
（P26b-L1）。**在墙已绑定的工作负载上，这是唯一能动地板的杠杆**；调度/
协议优化只能把实际时间压向地板。

### 4.4 模型边界（何时不可用）

- **爬行模式**（§7）：双峰、1400× 摆幅，不是平滑项——凡测量落入慢模式，
  该样本对模型校准无效（隔离丢弃，纪律同 P7 板况漂移）。
- **板况漂移**：跨批绝对值 ±40%（P7/P21-5），模型常数只在同板窗内自洽；
  A/B 必须同二进制背靠背（P21-5 律）。
- **未标定协议/机理**：β 的微观机理未判（4 个候选，6f-9 §3）；依赖段维
  `t_restart` 未定；C 流（S2MM）元素节拍是否与 A 流同值未分离测量；
  NoC 远端 L1 延迟（P28-3 环，实测 gather 全部 ≤20µs 故当前可忽略）。
  涉及它们的预测降级为 ±30% 置信带。
- **3.9µs 拟合是有效拍口径**：它把组成本 `t_g`、握手、段重启全摊进每
  元素（layerv2 单组形态下无法分离）；plain 多组形态的 132µs 独立即口径
  仍成立（P27-3b）。两口径不可直接相加。

## 7. 异常区：爬行与幽灵完成（模型的相变边界）

### 7.1 事实（全部实锤）

**爬行（P28-6f-6）**：
- 双峰：同设计同夹具 2.2ms ↔ 2832ms/exec（**1400× 摆幅**），无中间态主群；
- 慢模式逐元素节奏 0.4–1.5 ms/BD（干净 1.2 µs/BD），单 worker 尾巴可达
  470ms；"死锁"实为爬行重尾被 ERT 30s 超时接住；
- 概率随并发流数增长：N=8 ~1/8 exec，N=16 ~80%；
- 与内核无关（全哑也爬）、与 ring 无关（r0 也爬）、与 2-worker/shim 无关
  （N=8 同样出 1505ms 尾巴，概率低）；test_ring（每 worker 1 BD）恒快
  ⇒ **病随逐元素握手的规模而来**。

**提交路径判别（6f-7）**：同一 lv2probe 夹具 N=16——
- 引擎原始 ERT 包路径：**743µs 中位 ×12，0 slow**；
- pyxrt/XRT-runlist 路径：**~80% 尝试爬行（≤2832ms）**；
- N=8 全设计引擎路径 20/20 clean 754µs。
⇒ **probe 爬行病在 pyxrt/XRT 提交路径，不在数据流设计**。

**幽灵完成机理（6f-7，amdxdna 源码实锤）**：见 §2-5。syncobj 被信号 ≠
exec 成功；health 路径 memcpy 覆盖 regmap + TIMEOUT；health_reported 置位
后一切 cmd 瞬间 ABORT。

**全设计 N=16 引擎路径（6f-7 提出，6f-8 定案）**：exec0 = 60.8s 后"完成"
但 C 从未写入；exec1/2 = 1294/75µs 幽灵完成。**根因 = 引擎 full 分支 X
元素缺 `n@6404` 一字**（runtime-N 内核从 X 元素 [6404,6408) 读 worker 数，
design_layerv2.py:35 契约；probe 分支写两字、full 分支只写 id——fork 构造
不对称，P20b「怪设计前先核对夹具/内核契约」定律第三次咬人）。**不是设计
bug**：修复后 12/12 COMPLETED(4)、762µs med、C 5120/5120 非零、hash 跨
exec 恒定（确定性复算）。60.8s 看门狗的 fw 侧本体仍未定位，但 n 写对后
该路径不可达——问题 moot（6f-8 §1/§2）。

### 7.2 建模立场

爬行**不是模型内的平滑项**，是相变/拥塞区。模型的处理：
1. 校准纪律：凡慢模式样本一律隔离丢弃（同 P7 漂移纪律），模型只在干净
   支上标定与预测；
2. 尾部建模：工程上以 `(p_slow(N, path), Δ_slow)` 二元组承载——决策用
   p99/可用性，不用均值；
3. 机理定位交给 §7.3 的可检验假设，不进常数表。

### 7.3 候选机理排序（可检验假设，非定论）

| # | 假设 | 支持证据 | 判别实验 | 状态 |
|---|---|---|---|---|
| M1 | **pyxrt/XRT 提交路径软件病**（每 exec 重建 exec BO/runlist churn——P23 见 ~1930 create_bo/token；与 fw 通知路径交互） | 决定性：同夹具引擎路径 44+12 次 clean vs pyxrt ~80% 爬（6f-7） | xdump2 对拍两路径 ioctl/BO 序列；strace 计数；XRT 侧 exec BO 复用改造 | **开放（方向已定，机理未解剖）** |

律）；全设计 N=16 曾疑 M3，实为夹具契约字缺失（教训入 §8 静态检查器）。
**爬行与 36.6 钉子（§4.2 元素节拍）是两个正交现象**：前者是提交路径
疾病（双峰 1400×），后者是干净路径上的稳态结构税（六点稳定复现）。

用户方针（P28-6f-2）：修复方向"尽量去并行"而非靠分组容忍串行；锁死修完
后认真抽象**数据流建模工具/机制**——设计自描述 DAG + 可插拔派发模型仿真
+ 死锁见证环输出 + 吞吐预测；本周的爬行/幽灵完成/夹具契约事故作为首批
回归用例，兼作教科书案例。

### 8.1 核心抽象（四个 crate 级模块）

**A. Design IR（自描述 DAG）**——设计即数据，从 design_*.py 旁路导出或
手写：
- `Node` 变体：`ShimStream{shim, chan, bds, direction}`（BD 序列各自带
  bytes/粒度/axcache）、`Worker{tile, flavors, l1_footprint, bss}`、
  `RingFifo{depth, elem, home_tile, protocol}`、`Drain{wait_token}`、
  `HostStep{sync_kind, dirty_bytes}`。
- `Edge` = 资源占用声明（ShimChannel / L1Bank / Lock / NoC 远端访问 /
  BBPipe），每条边携带 §4.2 五维资源向量的贡献量——**元素数、段数
  （依赖链长度）、字节数是一等独立维度**，不许在设计里只写字节。
- 自描述的关键：BD 粒度与 fifo 协议（元素级 vs 大线性）进 IR，模型自动
  分账到元素维/字节维——这正是 6f-8/6f-9 教训（通道数优化了不绑定的
  维度）的机器可检形式。

**B. MachineModel**（xnpu-perf 已有骨架，扩维）：全部常数带 provenance
字符串 + 板窗声明；新增 `t_beat(elem, protocol)`、β 表、`t_restart`、
`t_exec`、完成语义状态机（§2-5）。

**C. DispatchModel trait（可插拔派发模型）**：
```rust
trait DispatchModel { fn simulate(&self, dag: &Design, m: &MachineModel) -> Timeline; }
```
实现：`IronGroupSerialized`（每组 fill→sync→drain 串行，P27-4 语义；
必须复现"ctrl 重排不减时"）、`FlomEnqueueAhead`（连续 BD 重填 + TCT 流内
数据依赖，P23-8）、`PersistentWorker`（P28-1）、`CrawlInjector`（按
p(N, path) 注入双峰慢模式——异常回归用，不进干净预测）。

**D. Analyses**：
1. **吞吐预测**：§3/§4 方程求值，输出 per-exec 五维分解表（%字节/%元素/
   %段/%通道/%计算 + 接棒预览"解除绑定维后谁接棒"），verdict 规则沿
   xnpu-perf（>100% 触发重校准而非判不可能）。
2. **死锁见证环（witness cycle）**：
   - 静态：资源分配环检测——BD 槽重用无 sync（P19b）、L1/.bss 越界
     （P28-6c rows-seed 踩踏）、流端口超限（P28-6d）、每核输出 DMA >2、
     **夹具/内核契约字核对（n@6404 类：设计声明的运行时参数必须在打包器
     输出里逐个在场——P20b 定律的机器化）**。
   - 动态：吃 6f-6 forensic 仪器输入（C 哨兵 drain 掩码时间线）→ 定位
     第一个停摆元素 → 反查 DAG → 输出见证环（谁持锁、谁等 fifo、环上
     每条边的资源维度账单）。
3. **协议审计**：每 shim 元素发行数 × t_beat vs 字节时间——元素维绑定
   的设计在编译期就亮红灯（本次 36.6 钉子若有此审计在 P28-4 即可预知，
   不必等到 6f-8 加宽实验）。
4. **回归套件**（全部来自本周实证）：
   - `crawl_bifurcation`：同 DAG × {engine, pyxrt} 派发模型 × CrawlInjector
     ——必须复现 743µs×12 clean vs ~80% 爬的路径分叉，否则 CrawlInjector
     参数错；
   - `ghost_completion`：wait 返回后校验状态字==COMPLETED(4) 且 C 哨兵
     已改写（6f-8 §2 的 TIMEOUT/ERROR 序列作为固定回放输入）；
   - `harness_contract`：n@6404 缺字 → 静态 witness 必须在仿真前抓到；
   - `widen_null_result`：N=8→16 的通道翻倍设计，模型必须预测零收益
     （n_shim 不变）——防止下一个"局部优化"再花一天板时；
   - `group_atom`：P27-4 三档 ctrl 手术在 `IronGroupSerialized` 下全部
     零变化。

## 9. 教科书章节骨架（本模型如何讲，5 节）

1. **从 roofline 到数据流账本**：为什么 per-op roofline 在 NPU 上不够
   （P3 的 130% 反例 → 分档；P10 "省 35ms"预测被 A/B 证伪）；成本核
   分解树 + provenance 纪律（数字不许裸奔）；TileSight 包络 + 第五维。
2. **器件层：墙、通道与元素节拍**：55.1 墙（P27-3b）与 16+16 通道律
   （P28-6a）；聚合非线性与"优化不绑定的维度"的两个处决案例（P12 通道
   假设、6f-8 加宽零收益）；元素数/段数/字节三维分离（6f-9）。
3. **执行模型与调度原子**：task group 原子性（P27-4 三连 NULL 的排除法
   教学）；persistent worker 与"组只能靠设计时消依赖来减少"（P27-4/P28-1）；
   逐元素锁握手 vs 无分段大流（v5s/FLM 同侧，layerv2 K 链另一侧）。
4. **一致性、地址路径与完成语义**：SYNC_BO 成本模型三版演进（P21-1 →
   P21-3 修正）；CLFLUSHOPT/SVM host-VA/axcache（P23/P24）；**syncobj ≠
   成功**——状态字、health 覆盖 regmap、幽灵完成链（6f-7/6f-8，源码级）。
5. **异常、漂移与模型边界**：双峰爬行不是平滑项（提交路径判别矩阵
   6f-7）；板况漂移与同窗 A/B 纪律（P7/P21-5）；反推式"验证"的危险
   （P26b 方法论）；仿真工具与回归用例（§8）——今天的每个坑都是明天的
   测试。

## 附录：模型总方程（一行版）

```
T_token = Σ_e [ t_g' + max( B_e/55.1 , n_shim·t_beat , B_e/(n_chan·6.95) , T_comp ) + t_seg + t_exec + t_sub ]
          + T_lm + T_host + K_flip·t_flip
t_beat = elem/(k_chan·6.95GB/s) + β·1.2µs   (β: 0 均匀 fill / ≈1 K 链分段)
前提：状态字==COMPLETED(4) 且输出哨兵改写（§2-5）；同板窗内（P21-5）
```

**模型的三个可证伪预言**（下一轮板测即检验）：(1) 消 K 链分段（窗口走
.bss）后 lv2 exec → ~520µs 附近；(2) 元素加倍（depth-1 大元素）后 exec
→ ~390µs（元素数减半、字节不变）；(3) W 改走 core mem-DMA 后元素维与
shim 解耦，聚合 → 50GB/s+。三者任一不成，β/元素维模型需要重审。
