## 1. 器件抽象与结构常数

### 1.1 被建模的机器（只列模型用到的结构事实）

- **阵列**：npu2 分区 = 计算核阵列 + shim DMA 行。整器件 8 shim 列 × 4 计算
  行 = 32 tile（P28-5）；我方 quad/pair 夹具所用分区 = 8 核（2 列 × 4 行）
  + 4 shim，"IRON 的 8 columns = 8 核，ctrl 列字段 0-3 = shim"（P27-3b）。
- **SHIM CHANNEL LAW**【实锤，静态推演 P28-6a】：每 shim 2 MM2S + 2 S2MM
  → 整器件上限 **16 入流 + 16 出流**。每 worker 1 A fifo + 1 C fifo ⇒
  **N=16 恰好饱和，N=32 在此协议下放不下**。
- **core↔core ObjectFifo = 共享内存 + 锁，不烧流端口**【实锤 P28-3】：
  npu_insts 零 aie.flow/stream 路由；缓冲+锁 home 于一个端点 tile，对端
  经 NoC 远端 L1 读写（acq 返回缓冲指针的 SPSC 队列）。约束因此是
  **L1 容量 + NoC 带宽**，不是流端口数；不相邻端点的 fifo 会拆成
  mem-DMA 流（每核仅 2 出）——HAM16 全单位步哈密顿环就是为了全部
  降形为零流量共享内存（P28-6d/6e）。
- **tile 资源**：计算核数据内存 64KB（4×16KB bank）、MemTile 256KB
  （docs/08 §4b）；PMEM 16KB/核（P19b：loader 只装 16KB，胶水恒 ~3052B；
  P28-4a 软浮点清剿）；栈窗 0x400（STACK LAW，P16/P17）。
- **上下文**：每 workload context 一个固件 ERT 实例，上限 16（docs/08；
  第 17 个 EINVAL），每 ctx 64MB host 指令缓冲（锁页根源）。

### 1.2 硬约束清单（可行性边界，不是时间成本；违反 = 编译期/挂死，不是慢）

| 律 | 内容 | provenance |
|---|---|---|
| SHIM CHANNEL LAW | ≤16 入 + ≤16 出流；每 worker 1+1 ⇒ N≤16 | P28-6a |
| CORE↔CORE FIFO 律 | 两端单步相邻 ⇒ 共享内存+锁；否则烧 mem-DMA（每核 2 出） | P28-6d（源码实锤） |
| STACK LAW | 栈窗 0x400；帧超限溢出写坏 fifo 流（静默） | P16、P17b |
| PMEM 16KB | CDO loader 只装 16KB；胶水 ~3052B；unroll 是 PMEM 之敌；≤16 trip 全展开 | P19b、P28-4a |
| L1 64KB/tile | OF depth × obj × 端点数 + .bss + 栈 ≤ 64KB | docs/08 §4b、P28-6e（高水位 ≤39.9KB） |
| ELEM%64==0 | load_v<256> 需 64B 自然对齐（depth-2 fifo 双元素缓冲） | P11 |
| AIE 向量对齐律 | 自然对齐外**截断不报错**；紧凑子区域 per-position 步长（48B）会静默越界 | P28-4c（反汇编实锤） |
| BD 维律 | ≤4 维/BD、每维 size ≤1023（10 位）、≤16 BD/通道、BD 槽号每组从 0 重数 | P12、P19b |

（§8）把它们做成静态检查器（design-time witness），先于任何时间预测。

## 2. 提交路径与完成语义（host 侧成本核 + 正确性律）

一次"运行"在 host 侧穿过以下成本核（全部可加、各自独立实测）：

1. **submit+syncobj 往返 `t_sub` ≈ 33–55 µs**【实锤 P1/P7/P26b-L3】。分桶
   随设备流量单调涨（1-4MiB 55µs / 4-16MiB 70 / ≥16MiB 82，P6）——大 op
   的 solo 里混入排队效应，不是纯 syscall。
2. **SYNC_BO 成本模型（P21-3 修正版，最终版）**【实锤】：
   `T_sync = t_syscall(1–5µs) + D_dirty × r`，其中脏行回写速率
   `r_kernel ≈ 0.2 ns/B（~5 GB/s）`、用户态 CLFLUSHOPT `≈0.03 ns/B
   （~32 GB/s）`；干净行近乎免费。**ToDevice → 用户态 CLFLUSHOPT**（严格
   等价，148KB 4.6µs）；**FromDevice → 必须保留 ioctl**：内核对 ctx BO 的
   MSG_OP_SYNC_BO fw fence 是正确性必需（syncobj 信号时 S2MM 尾写可能仍在
   NoC 途中，P21-3 决定性反例：差 98 字节全落 C BO 最后 128 行）。
3. **exec 边界 `t_exec` ≈ 30 µs**【实锤 P28-4e/5a】：相邻 exec 间的固件
   收尾/上下文交接。FLM 对照：整 token 1 ioctl、33 op 链在一个
   ERT_CMD_CHAIN 里（P23），边界成本被链结构摊薄到 ~µs 量级/层。
4. **cu_mask 翻转 `t_flip` ≈ 500–650 µs**【实锤 P9/P18/P27-3a/P28-5a】：
   fw PDI 重载。单 CU 全走一个 PDI 即免（P27-3a，−1.8ms/token）；lv2 路径
   唯一残留 = lm_head 在 CU1（每 token 1 次，P28-5a）。
5. **完成语义（正确性律，不是时间项）——signal ≠ 成功**【实锤 6f-7，内核
   源码】：`aie2_sched_notify` 在**所有**响应路径（COMPLETED/ERROR/
   TIMEOUT/ABORT/health）都 `dma_fence_signal`。exec BO header u32 的
   bits[3:0] 是状态字（0 INVALID / 1 NEW / 2 QUEUED / 3 RUNNING / 4
   COMPLETED / 5 ERROR / 6 ABORT / 7 SUBMITTED / 8 TIMEOUT / 9 NORESPONSE）。
   health 路径（fw 无响应）会把 health 数据 **memcpy 进 cmd BO 的 data 区
   （覆盖 regmap！）** 并置 TIMEOUT；一旦 `ctx->health_reported` 置位，后续
   所有 cmd 瞬间 ABORT+signal。⇒ **模型的一切"设备时间"都以状态字==4 且
   输出哨兵改写为前提**（§8 回归用例 b）。
   **全部预测已被仪器兑现**【实锤 6f-8 §2】：n@6404 bug 的病理 exec0 =
   TIMEOUT(8)@60.85s + pkt[1..8]=0xffffffff（health memcpy 覆盖 regmap 的
   指纹）；exec1+ = **ERROR(5)**@118–1297µs（fw 对 jammed 队列快速拒绝——
   修正 6f-7 猜的 ABORT）；C 全零 + hash 恒定 = 从未复算。另有一个未解开
   放问题：run-lv2loop 里 10KB C BO 的 FromDevice 恒 EINVAL（os 22，N=8/16
   都是），已用 clflush_region + 2ms settle 绕过（6f-7 §4）——fw-fence
   正确性风险由 hash 跨 exec 稳定性兜底，留观。

## 3. 分层成本核算框架（设备侧）

### 3.1 一次 exec 的分解树

```
T_exec = t_g' + max_r Σ_o u_r(o) + T_stall   （三维资源包络 + 加性停摆段，§4.2）
         r ∈ { 字节(DDR/NoC), 通道字节, 计算块 } ；T_stall = Σ胶水相位停摆
```

分解树各层（自上而下）：

```
exec ── host: submit(t_sub) → fw dispatch → [task groups] → TCT retire →
              syncobj signal（≠成功，§2-5）→ host 读回 coherency(§2-2)
group ── shim/fw 状态机固定成本 t_g + 组内 fill/compute 重叠 + 组末屏障
fill  ── 字节维 B/55.3 与 通道维 B/(n_chan·6.95) 取包络（P13 重叠律）
停摆  ── T_stall = Σ胶水相位停摆（§4.2）：K 口味边界上内核不 acquire
         A fifo → depth-2 排空 → 8/16 通道集体空转。各 worker 跑同一
         口味序列 → 停摆时间对齐 → 室友通道救不了。加性串行段，
         不进 max()（没有资源在消费，包络包不住空转）
```

多组 exec（pair/quad 形态）：`T_exec = Σ_groups T_group`（P27-3b【实锤】：
pair probe 547µs ≈ o(175) + gateup(378) 串行和 −6µs；**组间无重叠也无额外
罚金**——每组各付一次 `t_g`）。

多 exec token（lv2 形态）：

```
T_token = Σ_e [T_exec(e) + t_exec + t_sub]  +  T_lm + T_host_serial + K_flip × t_flip
```

### 3.3 关键结构性结论（模型的地基，全部实证）

1. **task group 是调度成本原子**【实锤 P27-4】：ctrl 级重排（输入侧 hoist /
   输出侧 hoist / 删 TCT）全部 NULL 或挂死 ⇒ 组固定成本**不在指令发行时序
   里**，在 shim/fw 对每组的状态机（drain token 集 + 组末 npu.sync 的完成
   路径）。P28-1 修正表述：我们的组末 8 条 npu.sync 是**对真实 drain 完成
   的长等待**，每条付 poll 量子 ~5-10µs × 8 ≈ 75µs；FLM 的 309 TCT 立即
   retire（等一个已完成 token ≈ 免费）。**组只能靠设计时不产生跨组数据
   依赖来减少**（依赖走内核内 L1/.bss 交接，不走 C→DDR→window 往返）。
   6f-9 §7 统一（镜像完成）：pair/quad 时代的胶水停摆本来就藏在组边界
   空转里（组间等 drain 时流反正停着）——「75µs/组」部分是胶水的
   遮蔽物；**组内的调度原子 = 胶水相位边界**，layerv2 消组后它裸露到
   流时间上。
2. **填充机器，不是计算**【实锤 P27-3b】：v5.4 双累加器内核计算完全藏于
   fill 之后（probe 去计算，时间不变）。当前所有 GEMV 形态的计算项
   `T_comp` 在 max() 里取 fill 支——模型对 decode 工作负载**默认计算免费**，
   除非引入新内核（届时按 P13 每块节拍重测）。
3. **聚合带宽形态相关（非线性）**【实锤】：单列 ~4–6.4 GB/s（P11 2.9–4.9 /
   P26 4.1 我方、6.4 FLM）；lv2 全系 36.1–37.6 且**对 N/环数/计算量全部
   不变**（6f-8/6f-9）；墙 55.1 只被大线性 BD 的 plain/pair 形态达到
   （P27-3b/P12）。终模型解释（6f-9 §7）：**流本身一直在墙上跑——
   36.6 GB/s = 55.6 × 占空比 δ（~2/3）**，胶水相位停摆把集体空转折算成
   带宽表观损失；不是任何带宽维度的差异。
4. **队列深度平坦**【实锤 P7】：深度 8→64 每 op 差 ≤4%；变异在**跑与跑
   之间**（板况漂移，同日 ±40%，P7/P21-5）⇒ 模型常数只在同批背靠背 A/B
   内有效，校准必须声明板窗。

## 4. 组合规则（怎么把成本核拼起来）

### 4.1 三条组合律

- **R1 组内取 max（fill/compute 重叠律，P13）**：稳态节拍 = max(t_fill,
  t_comp)/块。当前内核 t_comp 藏于 fill（P27-3b），退化为纯 fill。
- **R2 组间取和（P27-3b）**：同 exec 内多组 = Σ(每组 t_g + 组内 R1)。
  组间零重叠。跨组数据依赖（C→DDR→window 往返）额外把下游组的 fill 串到
  上游组的 drain 之后——这是 pair 比"流和"慢不出来的原因（547 ≈ 553），
  也是 quad 5 组 5×114 拼合的来源（P27-4）。
- **R3 exec 间取和 + host 串行段加和（P28-5 hostprof 闭合）**：
  `T_token = Σ T_exec + T_lm + T_host`。当前链是**零重叠**结构（wait 段
  25.77ms 独占）；FLM 的 host ~2.5ms 与 wait 重叠（双 runlist ping-pong，
  P5）——重叠是调度属性不是器件属性，模型两边都允许。

### 4.2 三维包络 + 第五维停摆段（6f-9 §6/§7 两轮再修正后的终模型）

**否证留痕（两级否证链，教科书金料）**：
- **第一版（每元素协议税）**：`BW_stream(L) = L/(L/BW_chan + t_bd)` 把
  1.2µs/BD 当**无条件每元素税**——lv2 两点碰对（N=8 36.6 vs 36.1 实测；
  N=16 加宽无收益 743 vs 754），被 **v5s 反例**否证【实锤 6f-9 §3】：
  同 18560B 元素、同 depth-2 协议，均匀 fill 的 v5s/plain 打满 55.1 墙
  （2.67µs/元素 = 纯带宽项），layerv2 K 链只有 36.6 GB/s（3.9µs/元素）。
  税不是元素的固有属性。
- **第二版（β 条件化的 shim 元素发行节拍）**：`n_shim × t_beat`，
  layerv2 β≈1、3.9µs/元素——六个引擎路径点闭合 <3%，但机制归因被
  6f-9 §6/§7 推翻：(a) **读设计**：lv2 是单 task group，fill 只有 3n
  条 BD（X/XN/W 各 n；W 塌缩为单条 1.74MB 线性大 BD）+ n 条 C drain
  （design_layerv2.py:351-374）——**shim 侧根本不存在逐元素发行**；
  (b) **plain v5 反例**：同元素、同协议、满计算，50GB/s 无逐元素税
  ——core↔shim depth-2 协议本身无罪；(c) **pair 夹具交叉判据**
  （P27-3b）：同 shim 2 A 通道 + 2D-tap C drain + K=1/K=3 胶水窗元素
  俱全，仍打到 **shim 聚合 13.8 GB/s（= 2×6.95 通道满速）**——「C
  drain 争用」与「双通道交错降速」两机制假设双双被此反例排除；若
  1.2µs 税是元素/发行属性，pair 不可能满速。⇒ **税既非元素属性也非
  发行节拍，是局部化气泡（bubble）**：元素间隔分布必为「大块 2.67 +
  段首长泡」形态（原判别实验已被分析裁决）。3.9µs/元素只是
  （墙 + 空转）÷ 元素数的重新参数化——元素数恒 ~190 是层几何的
  伴生不变量，**不是原因**。元素数不是独立资源维度。

**终方程【模型，闭合法见 §6】**——三维包络 + 加性停摆段：

```
T_exec = t_g' + max( B/55.3 , B/(n_chan·6.95) , T_comp ) + T_stall
T_stall = Σ_胶水相位 停摆(g) ， 停摆(g) = max(0, G_g − slack)
slack   = depth × t_elem   （depth-2 ≈ 2×2.67 = 5.3µs 的 in-flight 预跑量）
```

| 分量 | 公式 | 常数与 provenance | 绑定的设计形态 |
|---|---|---|---|
| DDR/NoC 字节 | `B/55.3` | 55.3 GB/s（P27-3b 四点拟合 55.1；P12 55.6） | v5s/plain/pair/lm 全系（lm 2660 = 132+2528 ✓）；**lv2 的流本体也在墙上** |
| shim 通道字节 | `B/(n_chan·6.95)` | 6.95 GB/s/通道（P12） | 单通道窄设计（P28-1：4/8 通道，~5.1 实测单点） |
| 计算块 | `blocks × t_comp` | ≈0（P27-3b probe；6f-9 zeros 复证） | 当前未绑定（新内核按 P13 重测） |
| **串行停摆段（第五维）** | `T_stall`（**加性，不进 max**） | lv2 240–257µs/exec；G_g 逐相位未测【推断】6f-9 §7 闭合反推 | **layerv2 全系**（36.6 钉子 = 55.6×δ，δ≈0.66）；v5s/P12/FLM ≈ 0（δ≈1） |

**为什么停摆段在 max() 之外（概念要点）**：TileSight 包络假设"总有一
个资源是瓶颈"；停摆段是**所有资源同时空转**的时间——胶水相位（K 口味
边界上 worker 做全向量 rms/swiglu/量化 + gather join，G_g 量级）期间
内核不 acquire A fifo → depth-2 排干 → 8/16 通道集体停；slack（in-flight
元素预跑量）先垫，垫完才暴露停摆。各 worker 跑同一口味序列 → 停摆
时间对齐 → **室友通道救不了**。没有资源在消费，max 包不住，只能加。
这就是第五维的正确形态：不是"另一种带宽"，是"**串行停摆段（胶水相位）
预算**"。表观聚合带宽 = 墙 × 占空比：**36.6 GB/s = 55.6 × δ（δ≈2/3）**。

三个形态在方程里的位置：
- **无分段大流（T_stall≈0，δ≈1）**：v5s 132µs + B/55.1 四点拟合、P12
  纯 fill 1.39µs/9280B（=1.34µs 带宽项零停摆）、FLM 算力列纯权重大流
  （P23-8 零激活 BD，TCT 串在流内当数据依赖）。
- **K 链交错（T_stall≈250µs，δ≈0.66）**：lv2 流内 K 口味交错（exec05
  头验证：[2048]×8, 101, 103×24, 104×24, 105×24, 102, [2048]×12）——
  胶水相位期间 W 流随内核相位走停。
- **pair/quad 多组形态（停摆被遮蔽）**：组间等 drain/TCT 时流反正停着
  ——「75µs/组固定成本」（P27-4）部分一直是胶水停摆的**遮蔽物**。
  layerv2 消组边界省了组开销，却把胶水**裸露**到流时间上。**单组设计
  的完成态不是免费流水，而是必须显式做胶水/W 重叠**（6f-9 §7 与
  P27-4 的统一，本模型的核心教科书点）。

**方程的直接工程推论**：
1. **加宽已死**（6f-8 §5 实证 + 终模型解释）：W_bytes 与 T_stall 都不
   随 N 变——W 总量由层几何固定（27.62→27.91MB，+1%），胶水逐 worker
   冗余跑全向量、口味序列相同→停摆时间对齐（条数与时长都不随 N 变）
   ⇒ N=8→16 聚合不动（36.1→36.6）、E2E 设备零收益（25.2→25.1ms）。
   通道翻倍是典型局部优化——它不碰任何一个绑定分量。
2. **唯一直接杠杆 = 胶水/流重叠**（6f-9 §7；目标 δ 0.66→~0.95）：
   (a) **内核分块穿插**——胶水本来就逐 256 向量 chunk 处理，每 chunk
   之间服务一个 W 块；受限于下一 op 块依赖胶水输出，必须**增量式**：
   o 块消费完立即累它的 sumsq 分量、gather 分段到达分段量化；
   (b) **胶水搬独立核**——16 核分区：8 gemv + 8 glue，quant 与 gather
   流水化；(c) **加深 fifo 缓冲**（slack 变大直接缩气泡，见推论 3）。
   上界：停摆基本遮住 → exec ≈ **505–520µs** → 33 exec ≈ 17ms 设备 +
   lm 3.2 + host ~2.5 ≈ **22.5ms/token ≈ FLM 21.44 追平点**。
3. **降级杠杆的占空比判决**（气泡 = max(0, G_g − slack) 的直接推论；
   旧三杠杆全部重新预言，见附录）：(a) **消 K 链分段**（窗口走 .bss）
   → **~740µs 不动**——窗口 fill 往返本来就 ≤20µs（r0≈full 已证），
   停摆在内核相位里，不在 fill 侧；(b) **元素加倍** → ~745µs——slack
   仅 5.3→10.7µs，五个相位共省 ~13µs；且 L1 放不下（2×37120+21KB >
   64KB，不可行）；(c) **W 走 core mem-DMA 同深度 → 零收益**——自环
   BD 不绕过 DDR/流停摆；只有当它带来**更深缓冲**（更多 in-flight 元素
   = 更大 slack）时气泡才按 max(0, G−slack) 缩短：深度 k×2 → 每 phase
   省 ~k×5µs。
4. **与 FLM 差距 = 纯占空比**（第三判据，【推断】与 P5/P23 自洽）：
   FLM 层 exec 480–585µs，流地板 27.13MB/55.1 = 492µs ⇒ **FLM duty ≈
   0.87–1.0；我方 27.62/754 = 0.66——同一堵墙，差距全部是占空比**。
   每层差 = 相同 ~500µs 墙项地板 + ~250µs 停摆 × 33 exec ≈ **8.4ms/
   token**——恰是 30.57 与 21.44 差距（9.1ms）的主体，余 ~0.7ms 在
   lm_head/host 侧。

### 4.3 量化密度：第一性杠杆（超越一切调度优化）

【实锤 P26b】两边（我方/FLM）都流 ~1GB/token 层+lm_head 权重，都在
~50-55GB/s 墙附近：

```
tok/s ≈ BW_eff / 每 token 权重字节        （P26 教科书要点，P26b 修正版归因）
T_floor = W_bytes(密度) / BW_wall
```

g64 共享 scale（0.5625→0.53 B/param）/ W3（0.41）⇒ 地板 18.9→17.8/13.8ms
（P26b-L1）。**在墙已绑定的工作负载上，这是唯一能动地板的杠杆**；调度/
协议优化只能把实际时间压向地板。

### 4.4 模型边界（何时不可用）

- **爬行模式**（§7）：双峰、1400× 摆幅，不是平滑项——凡测量落入慢模式，
  该样本对模型校准无效（隔离丢弃，纪律同 P7 板况漂移）。
- **板况漂移**：跨批绝对值 ±40%（P7/P21-5），模型常数只在同板窗内自洽；
  A/B 必须同二进制背靠背（P21-5 律）。
- **T_stall 是闭合反推量，非直接测量**【推断】：240–257µs 来自
  T_exec − B/55.3 的残差（6f-9 §7）；逐相位胶水时长 G_g、各口味边界
  （rms/swiglu/量化/gather join）的分摊都未分离测量。判别法（待做）：
  echo 时间戳计数器进 lv_cxn 探针窗——每胶水相位边界写 .bss 计数，
  比 6f-6 的 2ms 轮询细一个量级。在此之前涉及停摆分解的预测降级为
  ±30% 置信带。
- **W-fraction 判别可分离两分量**（6f-9 §6 判别实验，未做）：W 元素
  砍半后，fill 界 → T 降 ~250µs；停摆界 → T 降 ~120µs——实测落点
  直接裁决墙项/停摆项配比。
- **C 流（S2MM）侧贡献未分离**；不过 pair 反例（13.8GB/s/shim 带全套
  drain 与胶水元素）已排除「C drain 争用」作为降速机制。NoC 远端 L1
  延迟（P28-3 环，gather 全部 ≤20µs）当前可忽略。

  是因为 3.9µs/元素 =（墙 + 空转）÷ 恒定元素数——元素数是层几何的
  伴生不变量，不是原因。
- **教训：闭合 ≠ 机理**。两个机制不同的模型可以对同一组数据点闭合
  <3%；只有反例（pair/v5s）与设计读数（fill 条数）能裁决。这就是
  【推断】标注必须挂在 T_stall 上的原因。

**不闭合点（诚实台账）**：
- **T_stall 是闭合反推量，非逐相位直接测量**【推断】：240–257µs =
  T_exec − B/55.3 的残差；逐相位胶水时长 G_g、rms/swiglu/量化/gather
  join 各自分摊均未分离。判别法（待做）：echo 时间戳计数器进 lv_cxn
  探针窗。在此之前停摆分解类预测 ±30% 置信带。
- **W-fraction 判别未做**（6f-9 §6）：W 元素砍半 → fill 界 T 降 ~250µs /
  停摆界 T 降 ~120µs，实测落点直接裁决两分量配比。
- #14 的通道速率 ~5.1GB/s 是同点反推，无第二测点交叉验证。
- C 流（S2MM）贡献未与 A 流分离测量；pair 反例已排除「C drain 争用」
  作为降速机制，但逐流分账仍缺。
- 板况漂移（P7/P21-5）给一切对比 ±10-40% 批间带宽——上表全部取同板窗
  内数字，跨批引用需声明。

## 7. 异常区：爬行与幽灵完成（模型的相变边界）

### 7.1 事实（全部实锤）

**爬行（P28-6f-6）**：
- 双峰：同设计同夹具 2.2ms ↔ 2832ms/exec（**1400× 摆幅**），无中间态主群；
- 慢模式逐元素节奏 0.4–1.5 ms/BD（干净 1.2 µs/BD），单 worker 尾巴可达
  470ms；"死锁"实为爬行重尾被 ERT 30s 超时接住；
- 概率随并发流数增长：N=8 ~1/8 exec，N=16 ~80%；
- 与内核无关（全哑也爬）、与 ring 无关（r0 也爬）、与 2-worker/shim 无关
  （N=8 同样出 1505ms 尾巴，概率低）；test_ring（每 worker 1 BD）恒快
  ⇒ **病随逐元素握手的规模而来**。

**提交路径判别（6f-7）**：同一 lv2probe 夹具 N=16——
- 引擎原始 ERT 包路径：**743µs 中位 ×12，0 slow**；
- pyxrt/XRT-runlist 路径：**~80% 尝试爬行（≤2832ms）**；
- N=8 全设计引擎路径 20/20 clean 754µs。
⇒ **probe 爬行病在 pyxrt/XRT 提交路径，不在数据流设计**。

**幽灵完成机理（6f-7，amdxdna 源码实锤）**：见 §2-5。syncobj 被信号 ≠
exec 成功；health 路径 memcpy 覆盖 regmap + TIMEOUT；health_reported 置位
后一切 cmd 瞬间 ABORT。

**全设计 N=16 引擎路径（6f-7 提出，6f-8 定案）**：exec0 = 60.8s 后"完成"
但 C 从未写入；exec1/2 = 1294/75µs 幽灵完成。**根因 = 引擎 full 分支 X
元素缺 `n@6404` 一字**（runtime-N 内核从 X 元素 [6404,6408) 读 worker 数，
design_layerv2.py:35 契约；probe 分支写两字、full 分支只写 id——fork 构造
不对称，P20b「怪设计前先核对夹具/内核契约」定律第三次咬人）。**不是设计
bug**：修复后 12/12 COMPLETED(4)、762µs med、C 5120/5120 非零、hash 跨
exec 恒定（确定性复算）。60.8s 看门狗的 fw 侧本体仍未定位，但 n 写对后
该路径不可达——问题 moot（6f-8 §1/§2）。

### 7.2 建模立场

爬行**不是模型内的平滑项**，是相变/拥塞区。模型的处理：
1. 校准纪律：凡慢模式样本一律隔离丢弃（同 P7 漂移纪律），模型只在干净
   支上标定与预测；
2. 尾部建模：工程上以 `(p_slow(N, path), Δ_slow)` 二元组承载——决策用
   p99/可用性，不用均值；
3. 机理定位交给 §7.3 的可检验假设，不进常数表。

### 7.3 候选机理排序（可检验假设，非定论）

| # | 假设 | 支持证据 | 判别实验 | 状态 |
|---|---|---|---|---|
| M1 | **pyxrt/XRT 提交路径软件病**（每 exec 重建 exec BO/runlist churn——P23 见 ~1930 create_bo/token；与 fw 通知路径交互） | 决定性：同夹具引擎路径 44+12 次 clean vs pyxrt ~80% 爬（6f-7） | xdump2 对拍两路径 ioctl/BO 序列；strace 计数；XRT 侧 exec BO 复用改造 | **开放（方向已定，机理未解剖）** |
| M2 | **fw watchdog/health 交互 → 幽灵完成** | 源码实锤 + **预测全部兑现**：exec0=TIMEOUT(8)@60.85s + pkt[1..8]=0xffffffff（health memcpy 指纹）；exec1+=ERROR(5)@118–1297µs（6f-8 §2） | 已兑现；剩 60.8s 看门狗本体（fw 侧）不可达即 moot | **确认（ABORT 猜想修正为 ERROR）** |
| M3 | 全设计 N=16 独有数据流病（ring2/3 gather + K=1/K=3 窗口） | 曾是 6f-7 最小嫌疑集 | 根因实为 harness 缺 `n@6404`（6f-8 §1）；修复后引擎矩阵全绿 | **关闭（harness bug，非设计）** |
| M4 | DVFS/功耗状态机 | 在飞：xrt-smi pmode performance 锁频对照（P28-6f-6 结尾） | 锁频下 pyxrt 复测 | 弱化（爬行随提交路径判别，DVFS 难解释） |
| M5 | NoC/DDR 仲裁相位效应 | 无法解释提交路径判别 | — | 基本排除 |

现状小结：probe 爬行 = M1（pyxrt/XRT 路径疾病，引擎路径即类 FLM 的
1-ioctl-大链形态是免疫的）；幽灵完成 = M2（已实证，构成 §2-5 完成语义
律）；全设计 N=16 曾疑 M3，实为夹具契约字缺失（教训入 §8 静态检查器）。
**爬行与 36.6 钉子（§4.2 胶水相位停摆）是两个正交现象**：前者是提交
路径疾病（双峰 1400×、概率性、随流数增长），后者是干净路径上的稳态
结构停摆（六点稳定复现、确定性占空比损失 δ≈0.66——同名"慢"，机理、
分布形状（双峰 vs 单峰+固定残差）与修法（换提交路径 vs 胶水重叠）
完全不同。

## 8. 数据流建模工具设计（xnpu-dfsim 草案，Rust，引擎侧禁 C++）

用户方针（P28-6f-2）：修复方向"尽量去并行"而非靠分组容忍串行；锁死修完
后认真抽象**数据流建模工具/机制**——设计自描述 DAG + 可插拔派发模型仿真
+ 死锁见证环输出 + 吞吐预测；本周的爬行/幽灵完成/夹具契约事故作为首批
回归用例，兼作教科书案例。

### 8.1 核心抽象（四个 crate 级模块）

**A. Design IR（自描述 DAG）**——设计即数据，从 design_*.py 旁路导出或
手写：
- `Node` 变体：`ShimStream{shim, chan, bds, direction}`（BD 序列各自带
  bytes/粒度/axcache）、`Worker{tile, flavor_sequence, l1_footprint,
  bss}`、`RingFifo{depth, elem, home_tile, protocol}`、`Drain{wait_token}`、
  `HostStep{sync_kind, dirty_bytes}`。
- **`Worker.flavor_sequence` 是必填项**（不是可选注释）：模型从口味序列
  导出胶水相位边界——组内调度原子（6f-9 §7）。lv2 的 exec05 头验证
  序列（[2048]×8, 101, 103×24, …）就是该字段的实例。缺了它，停摆
  审计（D-3）无从做起。
- `Edge` = 资源占用声明（ShimChannel / L1Bank / Lock / NoC 远端访问 /
  BBPipe），每条边携带 §4.2 资源向量的贡献量——**字节数与通道数是
  一等独立维度**，不许在设计里只写 op 名。元素数不再是一等维度
  （终模型判它为伴生不变量），但 BD 粒度与 fifo 协议（元素级 vs 大
  线性、depth）仍进 IR——depth 决定 slack = depth×t_elem。
- 自描述的关键：这正是 6f-8/6f-9 教训（通道数优化了不绑定的维度、
  停摆藏在口味序列里）的机器可检形式。

**B. MachineModel**（xnpu-perf 已有骨架，扩维）：全部常数带 provenance
字符串 + 板窗声明；新增 `bw_wall`、`bw_chan`、**`t_stall`（总量标定
240–257µs/exec【推断】；逐相位 G_g 表待 echo 时间戳实验回填）**、
`slack(depth, elem)`、`t_exec`、完成语义状态机（§2-5）。带宽常数必须
带**占空比口径**：`bw_apparent = bw_wall × δ`，δ 由仿真输出而非手填。

**C. DispatchModel trait（可插拔派发模型）**：
```rust
trait DispatchModel { fn simulate(&self, dag: &Design, m: &MachineModel) -> Timeline; }
```
实现：`IronGroupSerialized`（每组 fill→sync→drain 串行，P27-4 语义；
必须复现"ctrl 重排不减时"，**且把胶水停摆记在组边界空转里——6f-9 §7
统一：pair/quad 时代的 T_stall 被组间等待遮蔽**）、`FlomEnqueueAhead`
（连续 BD 重填 + TCT 流内数据依赖，P23-8；**停摆=0 侧——无分段大流
的机器化身**）、`PersistentWorker`（P28-1）、`CrawlInjector`（按
p(N, path) 注入双峰慢模式——异常回归用，不进干净预测）。

**D. Analyses**：
1. **吞吐预测**：§3/§4 方程求值，输出 per-exec 分解表（%字节/%通道/
   %计算/%停摆 + 占空比 δ + 接棒预览"解除绑定维后谁接棒"），verdict
   规则沿 xnpu-perf（>100% 触发重校准而非判不可能）。
2. **死锁见证环（witness cycle）**：
   - 静态：资源分配环检测——BD 槽重用无 sync（P19b）、L1/.bss 越界
     （P28-6c rows-seed 踩踏）、流端口超限（P28-6d）、每核输出 DMA >2、
     **夹具/内核契约字核对（n@6404 类：设计声明的运行时参数必须在打包器
     输出里逐个在场——P20b 定律的机器化）**。

     每条边的资源维度账单）。
3. **停摆审计（glue stall audit）**：从 `Worker.flavor_sequence` 数出
   胶水相位边界，逐相位对账 `max(0, G_g − slack)` 预算 vs 字节时间；

4. **回归套件**（全部来自本周实证）：

   - `widen_null_result`：N=8→16 的通道翻倍设计，模型必须预测零收益

## 附录：模型总方程（终版）

```
T_exec  = t_g' + max( B/55.3 , B/(n_chan·6.95) , T_comp ) + T_stall
T_stall = Σ_胶水相位 停摆(g) ， 停摆(g) = max(0, G_g − slack)
slack   = depth × t_elem                     （depth-2 ≈ 5.3µs in-flight 预跑量）
T_token = Σ_e [ T_exec(e) + t_exec + t_sub ] + T_lm + T_host + K_flip·t_flip
占空比  δ = (B/55.3)/T_exec ；表观聚合带宽 = 55.6 × δ（lv2：36.6 = 55.6×0.66）
T_stall 取值：lv2 K 链交错 ≈ 240–257µs/exec【推断】；v5s/P12/pair/FLM ≈ 0
前提：状态字==COMPLETED(4) 且输出哨兵改写（§2-5）；同板窗内（P21-5）
```

**模型的三个可证伪预言（占空比模型翻新版，下一轮板测即检验）**：

1. **正向预言（修复方向）——胶水/流重叠**：分块穿插（增量式：o 块
   消费完立即累 sumsq 分量、gather 分段到达分段量化）或胶水搬独立核
   （16 核 = 8 gemv + 8 glue，quant/gather 流水化）→ lv2 exec →
   **505–520µs**、δ → ~0.95 → E2E ≈ **22.5ms/token ≈ FLM 21.44 追平点**
   （33 exec ≈ 17ms 设备 + lm 3.2 + host ~2.5）。若 exec 显著高于
   520µs，停摆未被完全遮住（逐相位 G_g 表需 echo 实验回填）；若低于
   505µs（≈ 字节地板 499 + 边界），模型错。
2. **反向预言（降级杠杆判决）**：(a) 消 K 链分段（窗口走 .bss）→
   **~740µs 不动**（窗口 fill 往返 ≤20µs 已证 r0≈full；停摆在内核
   相位不在 fill 侧）；(b) 元素加倍 → **~745µs 且不可行**（slack 仅
   5.3→10.7µs，五相位共省 ~13µs；L1 2×37120+21KB > 64KB）；(c) W 走
   core mem-DMA **同深度 → 零收益**（自环 BD 不绕过 DDR/停摆），仅当
   带来更深缓冲（深度 k×2）时每 phase 省 ~k×5µs。三者任一出现大幅
   收益，占空比模型即被证伪。
3. **测量判别预言**：(a) W-fraction 砍半：fill 界 → T 降 ~250µs；
   停摆界 → T 降 ~120µs——实测落点裁决墙/停摆配比；(b) echo 时间戳
   进 lv_cxn 探针窗：逐相位 G_g 直接可读，T_stall 从【推断】升
   【实锤】，气泡 = max(0, G_g − slack) 逐项对账。
