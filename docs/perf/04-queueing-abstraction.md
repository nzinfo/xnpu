# perf 笔记 04：排队论抽象 —— 数据流性能模型的再形式化

2026-09-29。问题：`02-dataflow-perf-model.md` 的 §7 占空比终模型
（`T_exec = W_bytes/55.3 + Σ胶水停摆`），用排队论的语言应如何抽象？
本笔记给出对象映射、三类排队论结构定律对本系统的精确对应、
每线视角的澄清、可证伪预言清单，以及 xnpu-dfsim 工具的形式化落点。
标记约定同 02（【实锤】/【模型】/【推断】），provenance 指 P 编号。

---

## 1. 对象映射（系统 ↔ 排队论）

| 系统实体 | 排队论对象 | 实测值 | provenance |
|---|---|---|---|
| fifo 元素（18560B） | customer | 到达**确定**（BD 链预排，非 Poisson） | design_layerv2.py 单 task group |
| DDR/NoC 聚合 | 共享服务台容量 C | 55.3 GB/s | P27-3b / P12【实锤】 |
| 每 shim DMA 通道 | 每线速率上限 µ | 6.95 GB/s | P12【实锤】 |
| worker 计算 | 串联后级服务台（状态相关） | compute 相位服务 / 胶水相位**休假** | 6f-9 §7 |
| A-fifo depth-2 | 有限缓冲 + **窗口流控**（credit=2，满则 backpressure） | slack = 2×2.67µs = 5.3µs | P11 depth-2 协议 |
| 胶水相位（K=101..105 边界） | **确定性休假**，各 worker 相位对齐 | ΣG ≈ 240–257µs | 6f-9 §7 闭合反推【推断】 |

统一抽象：setup、组边界、胶水相位在模型里是**同一对象——服务台不可用
区间**（unavailability interval），只有时长与相关性进入方程，成因不进。
（02 §3.3-1 的"遮蔽物"表述的形式化。）

## 2. 干净路径是确定性系统：核心是 max-plus，不是随机排队

干净路径上任何地方都**不形成排队队长**：缓冲占用是 0..2 的锯齿，
没有 backlog。系统是*周期受限*（cycle-time limited）而非*拥塞受限*。
确定性到达 × 确定性服务 × 有限缓冲 = 排队论的确定性极限 = **max-plus
线性系统**（Baccelli et al. 1992）：完成时刻满足
`x_{k+1} = max(前驱项) + 服务`，吞吐 = 依赖图的**关键回路**
（Karp 最大回路均值）。

两项式 `T_exec = B/55.3 + Σmax(0, G−slack)` 是该系统在**对称分区**下
关键回路的折叠形式【模型】。推论：xnpu-dfsim 的干净路径仿真器应解
完整 max-plus 系统（非对称设计下折叠式失效），CrawlInjector 才是
随机支的居所。

方法论警告【模型】：把随机假设（M/G/1 公式、均值等待）引入确定性
核心会**降低**预测力（当前 ε≤2%）同时增加参数。排队论对干净路径的
贡献是**分类学与结构定律**（下节），不是公式。与 TileSight 的确定性
footprint 哲学一致（01 笔记）。

## 3. 三轮否证链的排队论解读（教科书主课）

| 版本 | 停摆被放进的槽位 | 排队论判词 | 被谁杀死 |
|---|---|---|---|
| v1 元素税 β·1.2µs/elem | **服务时间 S**（per-customer inflation） | 休假混入 S ⇒ 错误预言"减元素数有收益" | v5s 反例（同 S 零税） |
| v2 发行节拍 n×3.9µs | **到达过程** | 到达确定；节拍化 ⇒ 错误预言"加通道有收益" | pair 反例（同到达 13.8GB/s/shim 满速） |
| v3 休假+有限缓冲遮蔽 | **server unavailability**（放对） | 休假独立于 S 与 λ，只与时长/相关性/深度交互 | 无反例；8+2 点闭合 ε≤2% |

**教训**：误放槽位（service vs arrival vs vacation）是性能建模最常见的
系统性错误；闭合 ≠ 机理（02 §6 已记），反例是唯一裁决。

## 4. 每线视角：聚合式的记账本质与死杠杆的结构证明

`36.6 GB/s = 55.6 × δ` 是记账恒等式；本体是**每线循环时间**：

```
T_exec = max_w [ W_w/µ_w + Σ_g max(0, G_g − slack) ]
约束对偶：µ_w ≤ 6.95（每线通道） 且 Σ_w µ_active ≤ 55.3（聚合墙）
```

- **N=8 数值简并**：8×6.95 = 55.6 ≈ 墙 55.3——两约束同时贴边（这本身
  是 DDR 仲裁公平的证据）；N=16 只剩聚合墙绑定。两种视角在 N=8 都闭合
  不是巧合，是对称分区的简并【模型】。
- 死杠杆的结构证明（不必再花板时）：
  1. 停摆是**每线自己的休假**，非服务台侧排队 ⇒ 通道侧手术（加宽/
     错峰/重分区）不动 `max_w` 的任何项。**错峰预言：ΔT=0**（只改
     聚合读数分解）；
  2. W 按线固定分片，别的线吃不了你休假腾出的通道容量；
  3. 唯二有效杠杆：缩短被遮蔽后的休假（切碎 G 到 ≤slack）或消灭
     休假本体（胶水搬独立核 = 把休假变成并行站）。

## 5. 遮蔽律 = 窗口流控 / BDP 尺寸律

遮蔽量 = 窗口 = depth × t_elem（带宽延迟积的离散版）。全遮 ΣG≈250µs
需 depth ≈ 250/2.67 ≈ **94 元素 = 1.7MB**，L1 64KB 物理不可行 ⇒：

- **加深 fifo 只对小 G 有意义**：depth 2→4 仅多遮 5.3µs/相位；
- **mem-DMA W 同深度零收益** = 缓冲干预不是速率干预；只有带来更深
  窗口才按 max(0, G−slack) 缩短气泡（02 §4.2 推论 3 的重述）；
- **glue/W 穿插 = 把长休假切成 ≤slack 的短休假**（exhaustive long
  vacation → interleaved/limited service）。**设计闸门：G_chunk ≤ 5.3µs**
  ——每处理一个 256 宽胶水 chunk（µs 级）必须回来消费一个 W 块。
  总量裁决工具：`tools/lv2_floor_pack.py`（T_full − T_floor = ΣG 直接
  测量，把【推断】升级为【实锤】的路径）。

## 6. 汇结站与闭网络

- **fork-join（gather）**：反同步化后汇结代价 ≈ E[max_N] − E[X] ≈
  σ√(2ln N)，σ 为板级抖动（µs 级）⇒ 预言穿插改造后 gather 仍 ≤20-40µs；
  若显著变大，瓶颈移到 **join 缓冲**（ring depth-2 SPSC 槽）而非通道
  ——不同修法，提前知道往哪查。
- **E2E 闭网络**：种群 K=1（host 逐 exec 等待）。Little：X = K/T。
  FLM 的 K=2（双 runlist ping-pong）把 host 串行藏进设备时间；我方
  host ρ ≈ 2.5/25.5 ≈ 0.1 远离饱和 ⇒ submit-ahead（升 K）安全、收益
  近全额、上限 = 设备站饱和。"重叠是调度属性"（02 R3）的排队论形式。

## 7. 随机支：爬行 = 双稳态相变

- 爬行特征（双峰无中间态、1400×、概率随流数、路径依赖：引擎免疫/
  pyxrt ~80%）= **负载相关服务退化的正反馈失稳**特征，非平滑项。
  建模为两状态机制切换链（clean↔congested），工程只认分位数（02
  §7.2 立场的形式化）。
- 板况漂移 = 环境非平稳（天尺度 ±40%），排队论不管，同窗 A/B 纪律
  吸收（P7/P21-5 律）。

## 8. dfsim 形式化落点 + 新增可证伪预言

- Design IR 新增一等公民：**每 worker 休假时刻表**（K 口味序列的
  抽象）与 **fifo depth（窗口）**；
- 干净路径仿真器 = max-plus 关键回路求解；DispatchModel 变体 =
  不同休假时刻表/窗口的组合；CrawlInjector = 机制切换链；
- 新增回归预言（并入 02 §6 验证表）：
  1. 只动通道/元素大小/错峰/分区的设计 → ΔT ≈ 0（N=16 已证，推广为
     一般预言）；
  2. G_chunk ≤ 5.3µs 穿插 → T_exec → B/55.3 + ε；收益显著低于此 ⇒
     gather join 或口味切换开销另有本体（模型的证伪出口）；
  3. ΣG 与逐相位 G_g 可由 floor-pack + echo 时间戳闭合（把 T_stall 的
     ±30% 置信带收窄）。
